# ai-review-poc

AI自動レビューの技術検証用リポジトリです（ダミーデータのみ）。
PRを作成すると、GitHub ActionsからGemini APIを呼び出し、レビュー結果をPRコメントとして記録します。

- 設計：AI連携基盤PoC 設計案 v0.2.1 ＋ 実装時の追加条件
- 自動マージ・デプロイは行いません。マージの判断は常に人が行います。
- `poc_app/` は架空の会費精算ツールで、実在のデータとは無関係です。

テスト（ネットワークに接続しない）: `python3 -m unittest discover -s tests -t .`

## PoC中の運用ルール（Gemini APIの呼び出し回数管理）

呼び出し回数の上限（合計70回）は、`.github/scripts/budget.py` がPRへの「予約記録コメント」で管理しています。次のルールを守らないと、上限管理が機械的に働かなくなります。

1. **予約記録方式の導入（PR #4のマージ）より前に作られたワークフロー実行は、再実行しない。**
   - 再実行すると、その実行が作られたときの旧コード（予約Artifact方式）が動きます。新しい予約記録コメントに数えられないまま、Geminiが呼ばれるおそれがあります。
   - 対象は、PR #4のマージ前に作られた `gemini-pr-review` のすべての実行です。具体的には、2026-11-18のPR #1〜#4に対する実行です。
   - レビューをやり直したい場合は、再実行ではなく、そのPRに新しいコミット（空コミットでも可）をpushしてください。
   - PR #4のマージ後に作られた実行であれば、再実行しても予約記録コメントで正しく数えられます。
2. **予約記録コメント（本文が `<!-- gemini-call-ledger -->` で始まる、`github-actions[bot]` のコメント）を削除・編集しない。** 削除すると、呼び出し回数が少なく数えられます。
3. **リポジトリ設定「Artifact and log retention」を90日未満にしない。** 実行履歴（`review-pr*`）の保存期間の前提です。
4. **このリポジトリへの手動のpushやPR作成も、呼び出し回数を消費します。** PoC中は、Claudeのテスト計画以外の操作を控えてください。Draft PRは消費しません。
5. **緊急停止**：Repository variables の `ALLOWED_ACTORS` を `[]` に戻すと、以後のGemini呼び出しはすべて止まります。

予約記録方式の導入前の実績（4回）は、`budget.py` の `LEDGER_BASELINE` に根拠とあわせて記載しています。
